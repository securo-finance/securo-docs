This guide covers deploying Securo to a production server. If you're just trying Securo locally, see the [Installation guide](/docs/getting-started/installation) instead.

## Production vs Development

Securo ships with two Docker Compose files:

| File                        | Use Case    | Images          |
| --------------------------- | ----------- | --------------- |
| `docker-compose.yml`        | Development | Builds from source, hot reload |
| `docker-compose.prod.yml`   | Production  | Pre-built images from GHCR     |

For production, always use `docker-compose.prod.yml`. It pulls optimized pre-built images from GitHub Container Registry instead of building from source.

## Server Requirements

- A Linux server (Ubuntu 22.04+ recommended) with at least **2 GB RAM** (the stack runs six containers)
- Docker Engine and Docker Compose plugin installed. Podman works too: use podman-compose **1.6.0 or newer**, older versions silently break the compose variable interpolation, which manifests as CORS and login-callback failures
- A domain name (optional, but recommended for HTTPS)

> The fastest path on a fresh server is the one-line installer, which does everything in the next two sections for you (including installing Docker and generating `.env`): `curl -fsSL https://usesecuro.com/install.sh | bash`

## Deployment Steps

### 1. Install Docker

On your server, install Docker using the official script:

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
```

Log out and back in for the group change to take effect.

### 2. Clone and Configure

```bash
git clone https://github.com/securo-finance/securo.git
cd securo
```

Create a `.env` file with a strong secret key:

```bash
echo "SECRET_KEY=$(openssl rand -hex 32)" > .env
```

If you want bank sync or exchange rates, add those keys too:

```ini
PLUGGY_CLIENT_ID=your-client-id
PLUGGY_CLIENT_SECRET=your-client-secret
OPENEXCHANGERATES_APP_ID=your-app-id
```

### 3. Start Securo

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

Verify all containers are running:

```bash
docker compose -f docker-compose.prod.yml ps
```

## Set FRONTEND_URL for Any Non-Localhost Access

If Securo will be reached at anything other than `http://localhost:3000` (a LAN IP, a domain, a tunnel), set `FRONTEND_URL` in `.env` to that exact public URL **before** people log in:

```ini
FRONTEND_URL=http://192.168.1.50:3000
```

This one variable drives CORS, bank-sync OAuth callbacks, OIDC redirect defaults, and passkey origins. Skipping it is the most common cause of "login works on the server but not from my laptop" reports. Restart after changing it: `docker compose -f docker-compose.prod.yml up -d`

To change the published ports, set `FRONTEND_PORT` and `BACKEND_PORT` in `.env`. On a hardened server you can keep the backend off the public interface entirely with `BACKEND_PORT=127.0.0.1:8000`; the frontend proxies `/api` to the backend internally, so nothing outside needs port 8000.

## Setting Up HTTPS

For production, you should put Securo behind a reverse proxy with TLS. Here's a minimal example using **Caddy** (which handles HTTPS automatically):

```bash
# Install Caddy
sudo apt install -y caddy
```

Edit `/etc/caddy/Caddyfile`:

```text
securo.yourdomain.com {
    reverse_proxy localhost:3000
}
```

Restart Caddy:

```bash
sudo systemctl restart caddy
```

Caddy will automatically obtain and renew a Let's Encrypt certificate. Update your `.env` to reflect the public URL:

```ini
FRONTEND_URL=https://securo.yourdomain.com
```

Then restart Securo: `docker compose -f docker-compose.prod.yml up -d`

## Backups

### Database Backup

Export the PostgreSQL database to a SQL file:

```bash
docker compose -f docker-compose.prod.yml exec db \
  pg_dump -U postgres securo > backup-$(date +%Y%m%d).sql
```

### Database Restore

```bash
docker compose -f docker-compose.prod.yml exec -T db \
  psql -U postgres securo < backup-20260401.sql
```

### Attachments and Other Volumes

The database is not the whole story: uploaded transaction attachments live in the `attachments` volume, and the agents knowledge base (if you enabled the optional AI feature) lives in `agent_knowledge`. A database-only restore silently loses every uploaded file, so back these up too:

```bash
docker run --rm -v securo_attachments:/data -v "$(pwd)":/backup alpine \
  tar czf /backup/attachments-$(date +%Y%m%d).tar.gz -C /data .
```

Restore by extracting into the volume the same way:

```bash
docker run --rm -v securo_attachments:/data -v "$(pwd)":/backup alpine \
  tar xzf /backup/attachments-20260401.tar.gz -C /data
```

### Automated Backups

Add a cron job for daily backups (cron runs with a minimal PATH, so use the absolute docker path):

```bash
crontab -e
```

```text
0 3 * * * cd /path/to/securo && /usr/bin/docker compose -f docker-compose.prod.yml exec -T db pg_dump -U postgres securo > /backups/securo-$(date +\%Y\%m\%d).sql
```

## Updating

Pull the latest images and restart:

```bash
cd /path/to/securo
git pull
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

The database migrations run automatically on startup (`alembic upgrade head`), so schema changes are applied during the update. Take a database backup before updating, and check the [releases page](https://github.com/securo-finance/securo/releases) for the notes of what changed.

## Monitoring

Check logs for any issues:

```bash
# All services
docker compose -f docker-compose.prod.yml logs -f

# Backend only
docker compose -f docker-compose.prod.yml logs -f backend

# Last 100 lines
docker compose -f docker-compose.prod.yml logs --tail 100
```

Check the health endpoint:

```bash
curl http://localhost:8000/api/health
```

## Troubleshooting

**Containers keep restarting**: Check logs with `docker compose -f docker-compose.prod.yml logs backend`. Common causes: not enough RAM, port conflicts (fix with `FRONTEND_PORT`/`BACKEND_PORT`), or, on Podman, podman-compose older than 1.6.0.

**Login or CORS errors from another machine**: `FRONTEND_URL` is missing or doesn't match the URL in the browser. See the section above.

**Database connection refused**: The database container might not be ready yet. It has a health check, but on slow servers it may take longer. Wait 30 seconds and try again.

**Out of disk space**: Docker images and volumes can consume significant space. Clean up old images with `docker system prune`.

**Permission denied on attachments**: The attachments volume needs to be writable by the container user. Check volume permissions with `docker compose -f docker-compose.prod.yml exec backend ls -la /app/data/`.
