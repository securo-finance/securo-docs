Recurring transactions let you define subscriptions and regular bills that repeat on a schedule. Instead of manually adding the same transaction each month, Securo can generate them for you automatically.

![Recurring Transactions](/screenshots/recurring.png)

## How It Works

A recurring transaction is a template that defines:

- **Description**: What the payment is for (e.g., "Spotify", "Netflix USD")
- **Amount**: The transaction value, including currency
- **Category**: one category, or a [split across several](#split-recurring-bills)
- **Frequency**: How often it repeats (weekly, biweekly, monthly, quarterly, twice a year, or yearly)
- **Weekend adjustment**: leave the date alone, or move an occurrence that lands on a weekend to the **Friday before** or the **Monday after**, the way a bank or an employer would
- **Next date**: When the next occurrence is due
- **End date** (optional): When the schedule stops generating occurrences
- **Status**: Active or paused

When the scheduled date arrives, Securo creates an actual transaction in the appropriate account based on the template. Generation runs automatically in the background every hour; each schedule also has an **auto-generate** toggle, and schedules with it off only create transactions when you click **Generate Pending**.

Monthly, quarterly, twice-yearly and yearly schedules preserve your intended day of the month: a subscription anchored to the 31st lands on April 30 and comes back to July 31. Editing the start date, day of month or frequency of an existing schedule moves its next occurrence to the first date of the new schedule, so projections follow the edit.

## Creating a Recurring Transaction

1. Navigate to **Recurring** in the sidebar
2. Click **+ Add Recurring**
3. Enter the description
4. Set the amount and currency
5. Choose the account
6. Select the frequency (weekly, biweekly, monthly, quarterly, twice a year, or yearly) and, if it matters, the weekend adjustment
7. Set the start date (and optionally an end date)
8. Click **Save**

### From a transaction

A bill you have already paid can become a schedule without typing it again. In the row menu on **Transactions**, choose **New recurring from this transaction**: the form opens filled with the description, amount, currency, direction, category (or split across categories) and account, monthly by default, with the transaction's day as the day of the month. The source transaction already counts as the first occurrence, so the schedule starts one period later and never generates it a second time. Later charges link to the schedule [like any other](#linking-to-real-transactions).

## Managing Recurring Transactions

At the top of the page, the month totals show what the active schedules expect as **Income**, **Expenses** and **Net**, in your primary currency; the arrows change the month. Every occurrence that falls in the month counts, so a weekly bill counts four or five times. Schedules in transfer or ignored categories stay out of the totals, and so do those without an exchange rate, with the count of each shown next to them.

The recurring transactions page shows a table with all your schedules:

| Column     | Description                                    |
| ---------- | ---------------------------------------------- |
| Description | The name of the recurring payment             |
| Amount     | The value and currency (with converted amount) |
| Frequency  | How often it repeats                           |
| Next Date  | When the next transaction will be generated    |
| Status     | Active or paused                               |
| Actions    | Edit or delete the schedule                    |

## Split Recurring Bills

A bill that covers more than one kind of spending, like an internet and streaming bundle, can be **split across categories** on the schedule itself, the same way as a [transaction](/docs/features/transactions#splitting-across-categories): **Split across categories** next to the category field, parts by **Amount** or by **%**.

- Every occurrence the schedule generates starts with the same split, sized to its amount
- A real charge [linked to the schedule](#linking-to-real-transactions) that has no category yet takes the split as well
- Changing the amount of the schedule resizes the parts in proportion; a split by percentage keeps its percentages
- Upcoming occurrences on the dashboard, in the calendar and in the [cash flow](/docs/features/reports#cash-flow) projection count each part in its own category, and the schedule list shows the parts on hover

## Generating Pending Transactions

Click **Generate Pending** to create all overdue recurring transactions at once. This is useful if you haven't opened Securo in a few days and need to catch up, or for schedules whose auto-generate toggle is off.

## Linking to Real Transactions

Recurring bills connect to the transactions that actually pay them. When a transaction (synced, imported or typed in) matches an upcoming occurrence on the same account with the exact amount, a similar description and a close date, Securo links it to the schedule instead of creating a duplicate, replacing the generated placeholder if one exists. A linked transaction can be unlinked from its edit dialog.

The threshold is a **matching rule** you can read and change: *Same account, exact amount* under **Rules → Matching rules → Recurring**. Widen its date window, lower the description similarity, or add a rule of your own that only suggests instead of linking. See [Payment Matching](/docs/features/reconciliation).

The **recurring badge** in the transaction list appears only on transactions actually linked to a schedule, so two purchases that merely share a description are never both marked as recurring.

## Price History

Linked charges also tell you when a subscription gets more expensive. **View price history** on a schedule lists every price its posted charges have had, with the date each change happened, and notes when a change came **after a gap** of several days without charges. A schedule whose price moved recently gets a **Price changed** badge, and the page sums up the **recent price changes (last 30 days)**. The history needs at least 3 matched posted charges before it says anything.

## Multi-Currency Subscriptions

For subscriptions in foreign currencies (e.g., a USD subscription on a BRL account), Securo shows both the original amount and the converted equivalent. This makes it easy to see the real cost of international subscriptions.

## Use Cases

- **Streaming services**: Netflix, Spotify, Disney+
- **Software subscriptions**: Cloud services, SaaS tools
- **Rent/mortgage**: Regular housing payments
- **Insurance premiums**: Monthly or annual insurance
- **Loan payments**: Regular debt repayments
