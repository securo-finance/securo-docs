Este guia descreve como implantar o Securo em um servidor de produção. Se você estiver apenas testando o Securo localmente, consulte o guia [Docker em Desenvolvimento](/pt-BR/docs/deployment/docker) em seu lugar.

## Produção vs Desenvolvimento

O Securo vem com dois arquivos Docker Compose:

| Arquivo                     | Caso de Uso | Imagens          |
| --------------------------- | ----------- | --------------- |
| `docker-compose.yml`        | Desenvolvimento | Compila a partir do código-fonte, hot reload |
| `docker-compose.prod.yml`   | Produção    | Imagens pré-compiladas do GHCR |

Para produção, utilize sempre o `docker-compose.prod.yml`. Ele baixa imagens otimizadas e pré-compiladas do GitHub Container Registry em vez de compilá-las a partir do código-fonte.

## Requisitos do Servidor

- Um servidor Linux (recomendado Ubuntu 22.04+) com no mínimo **1 GB de RAM**
- Docker Engine e o plugin Docker Compose instalados
- Um nome de domínio (opcional, mas recomendado para HTTPS)

## Passos para Implantação

### 1. Instalar o Docker

No seu servidor, instale o Docker usando o script oficial:

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
```

Saia e faça login novamente para que a alteração de grupo tenha efeito.

### 2. Clonar e Configurar

```bash
git clone https://github.com/securo-finance/securo.git
cd securo
```

Crie um arquivo `.env` com uma chave secreta forte:

```bash
echo "SECRET_KEY=$(openssl rand -hex 32)" > .env
```

Se desejar sincronização bancária ou taxas de câmbio, adicione essas chaves também:

```ini
PLUGGY_CLIENT_ID=seu-client-id
PLUGGY_CLIENT_SECRET=seu-client-secret
OPENEXCHANGERATES_APP_ID=seu-app-id
```

### 3. Iniciar o Securo

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

Verifique se todos os contêineres estão rodando:

```bash
docker compose -f docker-compose.prod.yml ps
```

## Configurando HTTPS

Para produção, você deve colocar o Securo atrás de um proxy reverso com TLS. Aqui está um exemplo mínimo usando o **Caddy** (que gerencia HTTPS automaticamente):

```bash
# Instalar o Caddy
sudo apt install -y caddy
```

Edite o arquivo `/etc/caddy/Caddyfile`:

```text
securo.seudominio.com {
    reverse_proxy localhost:3000
}
```

Reinicie o Caddy:

```bash
sudo systemctl restart caddy
```

O Caddy obterá e renovará automaticamente um certificado Let's Encrypt. Atualize seu arquivo `.env` para refletir a URL pública:

```ini
FRONTEND_URL=https://securo.seudominio.com
```

Em seguida, reinicie o Securo: `docker compose -f docker-compose.prod.yml up -d`

## Backups

### Backup do Banco de Dados

Exporte o banco de dados PostgreSQL para um arquivo SQL:

```bash
docker compose -f docker-compose.prod.yml exec db \
  pg_dump -U postgres securo > backup-$(date +%Y%m%d).sql
```

### Restauração do Banco de Dados

```bash
docker compose -f docker-compose.prod.yml exec -T db \
  psql -U postgres securo < backup-20260401.sql
```

### Backups Automatizados

Adicione uma tarefa no cron para backups diários:

```bash
crontab -e
```

```text
0 3 * * * cd /caminho/para/securo && docker compose -f docker-compose.prod.yml exec -T db pg_dump -U postgres securo > /backups/securo-$(date +\%Y\%m\%d).sql
```

## Atualizando

Baixe as imagens mais recentes e reinicie:

```bash
cd /caminho/para/securo
git pull
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

As migrações do banco de dados ocorrem automaticamente na inicialização (`alembic upgrade head`), portanto, as alterações de esquema são aplicadas durante a atualização.

## Monitoramento

Verifique os logs para identificar possíveis problemas:

```bash
# Todos os serviços
docker compose -f docker-compose.prod.yml logs -f

# Apenas o backend
docker compose -f docker-compose.prod.yml logs -f backend

# Últimas 100 linhas
docker compose -f docker-compose.prod.yml logs --tail 100
```

Verifique o endpoint de saúde:

```bash
curl http://localhost:8000/api/health
```

## Solução de Problemas

**Contêineres reiniciando constantemente**: Verifique os logs com `docker compose -f docker-compose.prod.yml logs backend`. Causas comuns: `DATABASE_URL` incorreta, `SECRET_KEY` ausente ou conflitos de porta.

**Conexão recusada com o banco de dados**: O contêiner do banco de dados pode ainda não estar pronto. Ele possui um health check, mas em servidores mais lentos pode demorar mais. Aguarde 30 segundos e tente novamente.

**Sem espaço em disco**: Imagens e volumes do Docker podem consumir muito espaço. Limpe imagens antigas com `docker system prune`.

**Permissão negada em anexos**: O volume de anexos precisa de permissão de escrita pelo usuário do contêiner. Verifique as permissões do volume com `docker compose -f docker-compose.prod.yml exec backend ls -la /app/data/`.
